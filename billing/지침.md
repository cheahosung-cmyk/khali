# 웰스타임 관리비 반자동 워크플로

고지서 사진을 올리면 클로드가 숫자를 읽어 세대별 관리비를 계산하고, 엑셀·고지서 문구까지 만들어 주는 시스템입니다. 관리소장님이 매달 할 일은 사진 업로드와 검침값 알려주기, 그리고 확인뿐입니다.

## 매달 하는 일 (소장님용)

1. **수도·전기 고지서 사진을 찍어 이 프로젝트의 새 대화에 올린다.** "8월 관리비"처럼 한마디만 덧붙이면 됩니다.
2. 클로드가 사진에서 읽은 숫자(수도 전체사용량·납기요금, 전기 기본요금·전기요금·전력기금, 사용기간)를 표로 보여주면 **맞는지 확인**한다. 사진이 흐리면 잘못 읽을 수 있으니 이 확인이 중요합니다.
3. **세대별 수도 검침값(t)** 을 알려준다. 예: "원유로 7, 에바돈카츠 38, …" (사진에 없는 유일한 정보입니다.)
4. 지난달 청구분 중 **입금된 금액**이 있으면 알려준다. 예: "드림스터디 100만원 입금됨". 안 알려주면 납부 0원으로 처리되어 전액 미납 이월됩니다.
5. 클로드가 계산 결과 표·엑셀 파일·세대별 고지서 문구를 만들어 주면 확인 후 발송한다.

세대가 들어오거나 나가면 그때 말씀해 주세요. `building.json`의 세대 목록을 고치면 지분율은 자동으로 다시 계산됩니다.

## 클로드가 할 일 (세션 지침)

사용자가 고지서 사진을 올리거나 "N월 관리비"를 요청하면:

1. **사진에서 값 추출**: 수도 고지서에서 전체사용량(t)·납기내요금·사용기간·검침일, 전기 고지서에서 기본요금·전기요금·전력기금·사용기간을 읽는다. **읽은 값을 반드시 표로 보여주고 사용자 확인을 받은 뒤** 진행한다. 읽을 수 없거나 애매한 값은 지어내지 말고 [확인필요]로 표시해 물어본다.
2. **세대별 수도 검침값을 요청**한다 (사진에 없음). 받기 전에는 계산을 확정하지 않는다.
3. **입력 파일 작성**: `billing/months/YYYY-MM.json`을 만든다 (기존 달 파일을 복사해 값만 교체). 지난달 입금액을 들었으면 `이번달_납부액`에 넣는다.
4. **생성 실행**: `python3 billing/generate.py YYYY-MM`. 전월 미납액은 `ledger.json`에서 자동으로 이월되므로 손으로 옮기지 않는다. 검침값이 나중에 오면 파일을 고치고 다시 실행하면 된다(재실행 안전).
5. **결과 전달**: 표준출력의 표와 검산 결과를 보여주고, `billing/out/YYYY-MM/`의 엑셀·고지서 문구 파일을 사용자에게 보낸다.
6. **커밋**: 입력 파일·ledger·산출물을 커밋해 월별 기록을 남긴다.

주지 않은 숫자는 절대 지어내지 않는다. 합계가 검산과 어긋나면 결과를 내보내지 말고 원인을 찾는다.

## 계산 규칙 (2026년 7월 실제 청구 엑셀 기준으로 확정)

- **세대는 2026년 8월부터 7곳**: 원유로(105), 와플칸/필이발소(108), 에바돈카츠(101), 아기고래(103), 카카오3F(301), 영종스크린4F(401), 드림스터디(501). 코브라독스(102)와 명성화로(201~203)는 퇴거 — 7월분까지 청구했고 8월부터는 부과 없이 미수금만 추적한다(`building.json`의 `"퇴거": "2026-08"`).
- **공용지분율** = 지분평수 ÷ 재실 세대의 지분평수합(7월까지 1000, 8월부터 767). 일반관리비에 쓰는 분양평수와 별개다(예: 와플칸은 관리비 10평·지분 9).
- **수도**: 단위요금 = 납기요금 ÷ 전체사용량. 세대상수도료 = 단위요금 × 세대 검침 사용량. 나머지 공용수도금액은 지분율로 배분.
- **전기**: 개별 계량이 없으므로 (기본요금 + 전기요금 + 전력기금) 전액을 지분율로 배분.
- **일반관리비** = 분양평수 × 4,000원. **부가세 10%는 일반관리비에만** 붙는다. 단 와플칸(필이발소)은 실제 청구에서 부가세 0원 — `building.json`에 반영돼 있음.
- **청소비품**: 세대별 고정값(4,400 / 1,320 / 3,100 / 1,320 / 2,640 / 19,600×4). `building.json`에 세대별로 저장.
- **미납·연체**: 전월 미납액은 ledger에서 자동 이월. 미납연체료 = 이월 미납액 × 1.5%를 **한 번만**, 원 미만 절사(실제 청구서와 동일). 연체료는 원금에 합산하지 않는다(복리 아님).
- **금액 단위**: 실제 발송분은 원 미만 소수까지 그대로 청구했으나, 새 시스템은 항목별로 원 단위 반올림한다(세대당 ±1원 안팎 차이).
- 발행: 웰스타임 관리사무소 / 입금계좌: 신협 137-010-094596 유성진 (웰스타임) / 납부기한: 매월 30일.

## 파일 구조

| 파일 | 역할 |
|---|---|
| `building.json` | 세대 목록·평수·단가·계좌. 세대 변동 때만 수정 |
| `months/YYYY-MM.json` | 그 달의 입력값 (고지서 숫자 + 검침값 + 입금액) |
| `ledger.json` | 세대별 미납 잔액. 스크립트가 자동 갱신 — 손대지 않기 |
| `generate.py` | 계산 + 엑셀 + 고지서 문구 생성 |
| `out/YYYY-MM/` | 그 달 산출물 (엑셀, 고지서 md) |

※ `months/2026-07.json`과 `ledger.json`에는 실제 발송된 7월 청구 엑셀(2026.07.26)의 값이 들어 있어, 8월부터는 고지서 사진만 올리면 이어서 계산됩니다.

## 확인이 필요한 것 (다음 달 전에)

실제 7월 청구 엑셀을 분석하면서 발견한, 소장님 확인이 필요한 항목입니다.

1. **코브라독스 7월분 173,538원**: 실제 7월 배분에는 코브라독스 지분이 포함되어 있었는데 퇴거가 확정됐습니다. 이 금액을 받을 수 있는지(못 받으면 미수금 처리) 확인이 필요합니다. 현재 ledger에는 미수금으로 잡아 두었습니다.
2. **청소비품 산정 근거**: 세대마다 4,400/1,320/3,100/2,640/19,600원으로 제각각인데 일정한 공식(평수 비례 등)이 보이지 않습니다. 지금은 그대로 고정값으로 두었으니, 바뀌는 규칙이 있으면 알려주세요.
3. **와플칸(필이발소) 부가세 0원**의 이유(간이과세 등)를 확인해 두면 좋습니다.
