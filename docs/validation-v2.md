# 리포트 검증 v2

이 변경은 성과 집계와 데이터 품질을 바로잡는다. 수익성 개선을 입증한 전략 변경은 아니다. 자동매매나 실제 주문은 추가하지 않는다.

## 확인한 문제

- 기본 브랜치 21be42df99bd446a060f3a3695265c2be0d34d35의 10월 15일 리포트는 606건, 평균 -3.5%, 승률 37%, 초과수익 +2.2%p다. 546건/-4.4%/25%/-1.9%p는 현재 원문에서 확인하지 못했다.
- 10월 14일 issue #95는 600건/-3.4%/36%/+4.4%p다. 서로 다른 날의 누적 집계이며, 같은 표본의 고정기간 비교가 아니다.
- 기존 tracking은 퀀트 후보 전체를 저장해 최종 탈락 종목도 성과에 포함한다. 5달력일 이상 지난 신호의 서로 다른 보유기간 수익률을 단순 평균했다. 지수가 없는 경우 초과수익 분모도 달랐다.
- 원래 이력 74개, 후보 이벤트 624개, 고유 시장·티커 60개, 최초 등장 이후 반복 이벤트 564개. 반복은 오류 자체가 아니지만 독립된 투자 건수로 해석할 수 없다.
- 현 실행 환경에서 네이버 구주소는 HTTP 200의 Npay 증권 화면을 반환했고 table.type_2가 0개였다. 실제 KR dry-run에서도 `네이버 KOSPI 1페이지 테이블 없음`을 재현했다. 이는 현재 파서 호환성 실패를 입증하지만 10월 15일 GitHub 러너의 원시 응답을 소급 입증하지는 않는다.

## 설계 검토와 결정

데이터 엔지니어링 관점에서는 미수집 상태를 실패로 드러내야 한다. 반면 운영 관점에서는 한국 실패가 미국 리포트까지 중단시키면 안 된다. 따라서 시장을 격리하고 실패 사유를 보고하며 해당 시장 추천만 보류한다.

통계 관점에서는 누락된 발행 시각을 임의 복원하면 결과를 왜곡한다. 반면 연구 관점에서는 기존 기록을 버리면 비교가 단절된다. 기존 파일은 보존하고 새로운 집계에서 `unknown_publication_time`으로 표본 수를 명시한다. GitHub 게시 시각·정확한 대응 스냅샷이 검증된 후에만 별도 이관할 수 있다.

리스크 관점에서는 뉴스·업종 미확인 종목을 제외해야 한다. 반면 선별 관점에서는 추천이 줄어들 수 있다. 안전한 초기 운영을 위해 관찰 목록으로 분리하고, 효과 검증 전 기준을 완화하지 않는다. 뉴스가 없거나 날짜 미상이면 악재가 없다고 해석하지 않는다.

투자 연구 관점에서는 기존 점수의 문제도 의심해야 한다. 반면 검증 관점에서는 집계가 잘못된 채 가중치를 바꾸면 개선 원인을 구분할 수 없다. 먼저 집계를 수정하고 가치/모멘텀 가중치는 유지한다. 모의 상한은 종목 10%, 업종 25%, 최대 5종목이며 최적값이나 실제 보유 비중이 아니다.

## 다음 실행부터의 동작

1. 한국 XKRX·미국 XNYS 달력에서 직전 완료 거래일을 계산한다. 장중 봉은 피처에서 제외하며 후보별 기준일이 다르면 추천 보류한다. 달력의 임시 휴장 반영 지연도 있을 수 있어 공급자와 불일치 시 보류한다.
2. 시장 수집률 95% 미만 경고, 90% 미만 추천 보류. 미국은 시세 유효 피처/유니버스와 재무 조회 성공/사전 필터 대상 비율이다. 한국의 listing_coverage는 두 시장 페이지 완주 여부이며 독립적인 전체 상장 종목 대비 비율이 아니다. 진단 항목을 혼동하지 않는다.
3. 핵심 가격·재무·배당 결측, 재무 기준일·업종 미확인, 최근 7일 뉴스 조회 실패·날짜 미상·기사 없음, 악재 키워드가 있으면 관찰로 분리한다. 뉴스 키워드는 거짓 양성·거짓 음성이 있으며 공시 검증의 대체물이 아니다.
4. 목표주가 작성일은 현재 소스에서 확인하지 못하므로 명시적으로 미상으로 기록한다. 목표주가 단독으로 고평가나 가치 함정을 확정하지 않는다. 공시·실적 일정 미검증이 남아 있으므로 모든 후보의 확신도는 최대 중이다.
5. AI는 후보별 JSON 판정만 반환한다. 알 수 없는 티커·중복·누락·형식 오류가 있으면 전체 AI 판정을 버린다. 품질 게이트는 AI가 우회할 수 없다. 성과 표는 단일 집계 결과에서 생성한다. 독립 전문가 25명의 표결이라는 표현은 제거한다.
6. 보고서와 이력은 실행별 파일로 저장한다. 기존 보고서·이력은 수정하지 않는다. 실제 issue의 createdAt을 기록하고 초 단위 정밀도를 고려해 1초 뒤부터 이용 가능했던 것으로 보수적으로 평가한다. 이력 저장·발행 시각 기록이 실패하면 워크플로가 실패하도록 한다.
7. 발행 후 시작하는 첫 거래일 **종가** 진입, 그 뒤 **5·20·60거래일** 종가 청산. 시가 진입이나 5달력일 평가가 아니다. 종목·지수의 정확히 같은 날짜 값이 없으면 대체 날짜를 쓰지 않는다.
8. 퀀트 전체와 최종 통과/조건부 통과를 시장별로 별도 집계한다. 절대수익 표본 수·초과수익 표본 수·기간 미도래·누락·오류를 공개한다. 한국은 KOSPI/KOSDAQ을 구분해 각각의 지수를 사용한다. 과거 시장 구분이 없으면 추정하지 않는다.
9. Yahoo Close(auto_adjust=False)를 사용하는 현지통화 가격수익률이다. 배당·환율은 제외한다. 원시 가격 CSV, 입력 이력 해시, 집계 JSON을 저장한다. 분할·합병 등 기업행위 시세는 공급자의 처리 여부를 별도로 확인해야 한다.

## 실행 및 검증

```bash
pip install -r requirements.txt
python -m unittest discover -s tests -v
python -m compileall -q stock_analyst tests
python -m stock_analyst.backtest --audit --output reports/audits/history-audit.json
python -m stock_analyst.backtest \
  --history tests/fixtures/history \
  --prices tests/fixtures/synthetic-prices.csv \
  --asof 2026-10-15T22:10:00Z \
  --output reports/audits/synthetic-backtest-check.json
```

합성 시세에서는 TEST 100→110, 지수 100→105로 5거래일 수익률 10%, 초과수익 5%p를 확인한다. 왕복 0/20/50bp 비용이 커질수록 순수익이 감소하며, 동일 기간 중복 신호 제외와 최종 탈락 제외를 확인한다. 합성 자료의 결과는 실제 종목의 성과가 아니다.

실제 시세 CSV는 `date,symbol,close` 형식이고 지수도 포함해야 한다. 미국 지수는 ^GSPC, 한국은 ^KS11/^KQ11, 한국 티커는 .KS/.KQ 접미사다. 신규 실행은 성과 계산에 쓴 시세 CSV와 해시를 reports/evaluations에 저장한다. 백테스트는 네트워크 없이 이 자료로 재현할 수 있다.

## 아직 입증하지 않은 부분과 중단 기준

- 한국 신규 화면에 맞는 수집기 교체·전체 후보 복구는 이 변경에 포함하지 않는다. 기존 파서가 실패하면 한국 추천을 보류하고 오류를 노출한다. 확인되지 않은 대체 API로 ROE·재무 기준일을 추정하지 않는다.
- 과거 발행 시각·최종 판정·한국 상장시장 구분의 검증된 이관이 없으므로 기존 624건의 새 기준 실제 수익률 재계산은 미완료다. 기존 수익률과 신규 집계는 직접 비교하지 않는다.
- 당시 전체 재무·뉴스·유니버스가 없어 가치/모멘텀 단독 및 가중치 변경, 뉴스 필터 추가의 과거 효과는 아직 검증 불가다. 현재 데이터를 과거에 대입하지 않는다.
- 신호별 평균은 포트폴리오 수익률이 아니다. 자금 제약·회전율·배당·세금·환율·상장폐지·갭 체결·손절·최대낙폭·워크포워드·블록 부트스트랩은 별도의 포트폴리오 백테스트가 필요하다. 이 변경의 상한 비중으로 수익성 개선을 주장하지 않는다.
- 외부 유료 AI의 실제 JSON 응답은 호출하지 않고 모의 응답으로 검증했다. 라이브 응답의 형식 검증 실패 시 추천은 자동 보류한다.
- CI 테스트 실패, 이력 저장 실패, 발행 시각 기록 실패 시 게시 워크플로가 실패한다. 시장 수집·품질 실패 시 해당 시장을 관찰/실패로 처리한다. 이전의 느슨한 추천으로 자동 복귀하지 않는다.
